7. 鼠标停在「判定 ACCEPTED」「通过用例」「耗时 / 内存」三处各 1 秒。

**正确版（埃氏筛；错误版只改带注释那一行）**：

> 注意函数式提交必须带 `class Solution` 包裹（编辑器骨架长这样，直接在骨架里填就行），参数名随意。

```java
class Solution {
    public int countPrimes(int n) {
        if (n < 2) {
            return 0;
        }
        boolean[] isPrime = new boolean[n];
        java.util.Arrays.fill(isPrime, true);
        isPrime[0] = false;
        if (n > 1) {
            isPrime[1] = false;
        }
        int count = 0;
        for (int i = 2; i < n; i++) {
            if (isPrime[i]) {
                count++;
                for (int j = i + i; j < n; j += i) {
                    isPrime[j] = false;   // ← 错法：把 false 写成 true，合数全被当成质数
                }
            }
        }
        return count;
    }
}
```

> 错法效果可复现：标记写反后每个数都被当成质数，`[10]` 算出 8（期望 4）、`[100]` 算出 98（期望 25），而 `[0]`、`[2]` 不进筛仍通过——正式提交 2/4 WRONG_ANSWER，试运行 [10] 直接 0/1。
> **不要**把 `class Solution` 去掉：harness 会在代码后面拼一个调用 `Solution` 的 `Main` 类，少了包裹就是编译错误（judge0 下真实可见 COMPILATION_ERROR）。

**口播（290 字，约 72 秒）**：

## 3. 录制与剪辑操作规范

1. **分两段录，不要一条过**：先录教师链（S9），再录学生链（S0–S8、S10）。避免中途换号、中断节奏。
2. **每段多录一条备用**，尤其是 S4（判题）和 S5（AI 报告）。
3. **口播优先**：宁可画面慢半秒，也不要出现「画面已经到下一屏、声音还在讲上一屏」。
4. **等待要压缩**：判题等待、AI 生成、页面加载，剪辑时压到 0.5–1 秒，但**不要剪掉状态变化过程**（如「已判定」出现的那一下）。
5. **字幕**：全片烧中文字幕（赛事允许配字幕，评委常静音看片）。术语字幕单独做花字，别只做对白字幕。
6. **音量**：对白 −18 到 −12 LUFS，背景音乐 −28 以下或不用。技术演示片不需要 BGM 撑情绪。
7. **分辨率**：导出 1920×1080、H.264、30 或 60fps，MP4；文件名 `AI编程实训助手-演示视频-团队名.mp4`。
8. **片头不超 3 秒**、片尾不超 5 秒，别把时间花在转场上。

## 4. 风险预案（录之前先读一遍）

| 风险 | 现象 | 处置 |
| --- | --- | --- |

编程课上最难受的一句话，是「写完等老师看」。我们想把它换成：交上去，几秒钟就有依据。//

这是 AI 编程实训助手，一个面向编程课的教学平台。先说问题：编程课的教学闭环，最容易断在三个地方。/ 第一，练习没有反馈——学生写完只能等老师看，一次作业的反馈周期以天计，练不动。/ 第二，判分口径不统一——不同助教对同一份填空给分差很多，学生不服气，老师也说不清依据。/ 第三，学情看不见——谁在练、练到哪、卡在哪，散在聊天记录里，期中才发现有人掉队。/ 我们把这三件事串成一条链：写代码、机器判题、AI 给分并说明依据、教师复核、成绩发布，过程再进积分和看板。//

这是演示学生账号。登录后第一屏不是空看板，而是「下一步该做什么」。/ 最上面这张 AI 批改与辅导卡片，取的是他最近一次已判定的提交：批改结论加推荐练习，一屏说完，点一下直接进去。/ 下面依次是学习进度、考核安排、积分和排名。这些数字全部来自真实的提交和成绩，没有一条是写死的。//

从左侧「题库」进入练习。每题带难度和知识点标签，可以按标题搜、按难度筛，右上角还有「AI 出题」，一会儿单独看。/ 旁边是力扣 Top 100 题单：已收录二十六道，没收录的点开直接走 AI 出题，知识点、难度都预填好，不用人工写测试用例。/ 点开一道题：题干、输入输出格式、示例、练习测试点都在左边，右边是代码区。/ 这道题是函数式判题——学生只填函数体，服务端按 countPrimes 的签名套一层 harness 生成完整程序，语法细节不干扰考核重点。//

正式考核走另一条入口：考核列表、考核详情、做题。平台支持 Java、Python、C++、JavaScript、Go、Rust 六种语言，这道题只开放 Java——函数式判题，编辑器已经按 countPrimes 的签名生成好骨架，我们只填函数体。/ 我们先故意写错一版：筛法里标记合数的那一行，把 false 写成了 true，所有合数都被当成质数。点「试运行」。这不是前端演的动画——请求真的发到服务端判题机，代码在隔离沙箱里编译、执行，回来的是这次运行真实的耗时和内存；失败的测试点把输入、期望输出、实际输出并排列出来，错在哪一眼能看到。/ 试运行每次只随机抽一个测试点，而且每分钟最多十次，防止有人拿它当答案探测器。/ 现在提交这一版，判定未通过，通过用例二比四，这条记录会进提交历史和后面的批改报告。把那一行改回来再提交一次——这次判全部测试点，判定 ACCEPTED，通过用例四比四，耗时几百毫秒。//

判完只是开始。点开「批改报告」，一页给全三件事：结论、错因、下一步。/ 上半部分是判题事实：哪几个测试点没过，真实耗时和内存，都是判题机回的原值。/ 下面是 AI 批改。模型是 Mimo 的 mimo-v2.6-flash，走开放兼容接口，密钥从环境变量注入，不进代码、不进仓库。/ 它不给「继续加油」这种话，而是按编译错误、运行错误、超时、答案错误分别解释，再给几条能马上动手的建议。/ 这里有个刻意的取舍：提示词明确要求不给可以直接提交的题解——批改不能变成抄答案。/ 最后是推荐下一题，这一条是规则不是模型：做对升一档，做错同难度补练；先在本场考核里找，找不到再全库找，都没有就如实显示没有，不硬凑。/ 报告只读，不写成绩、不写积分、不改任何一张表；同一份提交的结论缓存三十分钟，刷新不重复计费。//

AI 的第三个落点是助教。它不绑定某一次提交，随时能问知识点。/ 左边是自己的会话，可以新建、改名、删除；也可以关联一道题，让回答结合题面。/ 历史不在浏览器里——会话和消息都落库，服务端按会话取最近十二条进提示词，所以刷新、换电脑，对话还在。/ 权限只有一条：会话必须属于本人；访问别人的会话 id，和不存在的 id 一样返回 404，不能用编号去猜同学问了什么。//

同一页的第二个标签是学习画像。/ 尝试题目、通过率、已发布成绩均分，都由后端在读取时聚合本人已判定的提交和已发布的成绩，写进快照表，每次打开都刷新。/ 薄弱知识点只取「尝试过、至少有一题没通过」的标签；推荐练习只从公开题库里挑还没通过的，优先命中最薄弱那个。/ 做错的题会自动进错题本：AI 给的错因一句话就写在列表里，点「重做」回到做题页，上次写错的代码原样带回来，改一处再练一遍，不用从空白开始。/ 一个新账号打开画像会明确显示没有数据，而不是拿零通过率冒充画像。//

题库里的 AI 出题：学生给一个知识点和难度，模型生成题干、样例、参考解和测试点。/ 关键不是「生成」，是「自检」——服务端拿参考解把所有测试点真跑一遍，全部通过才发布；没过就把失败原因回喂给模型重试一次，两次都不过就明确报错，不把一道做不对的题塞进题库。/ 生成过程可以取消，取消之后不落库。/ 配额是每人十分钟六道，因为每一次生成背后，都是一次模型调用加一轮真实判题。//

学生这一侧走完，看教师这一侧。/ 阅卷页一次把整场考核的题干和进度拿全，不用一题一题回查；客观题按标准答案自动判，填空题左右分栏人工过。/ 全部批完才允许发布，发布之后学生才看得到成绩，没参加的考核不显示零分。/ 日报周报走同一套 AI 评分：按写在代码里的评分标准给一到三档，只看内容的具体性、可检验的收获和反思，不按篇幅和文风加减分；人工结果永远优先于 AI。//

技术底牌一句带过：Spring Boot、Vue 3，自建 Judge0 做真实判题，AI 走开放兼容接口，密钥全部环境变量注入，权限在后端逐对象校验。/ 后端二百五十六个测试、前端二百九十四个用例，全部通过。/ 我们想做的事很简单：让编程课的反馈周期，从以天计，变成以秒计。
