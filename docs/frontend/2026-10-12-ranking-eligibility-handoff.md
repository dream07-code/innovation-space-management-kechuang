# 前端修改交接：方向负责人不计入积分排行榜

日期：2026-10-12  
状态：业务规则已确认  
适用范围：学院科创空间管理系统前端

## 规则

1. 积分排行榜、排名人数、名次和同分跳位仅统计 `ACTIVE` 学生。
2. `DIRECTION_LEADER` 和 `COLLEGE_ADMIN` 不进入总排行榜、方向排行榜或个人排名。
3. 方向负责人仍可提交日报/周报、获得并保留积分和积分流水，也可查看总榜和方向榜。
4. 不清零负责人积分，不删除积分流水，不改变报告和评分页面。
5. 前端不得自行按角色过滤排行榜行。后端必须从查询层排除非学生，保证 `items`、`total`、rank 和同分计算一致。

## 前端任务

- [ ] `DIRECTION_LEADER` 导航隐藏或禁用“我的排名”。
- [ ] 负责人个人首页移除总排名、方向排名卡片；保留积分、积分流水和报告状态。
- [ ] 如果旧路由仍可直接访问 `/rankings/me`，负责人显示空状态“方向负责人不参与积分排行榜”，不要请求或伪造排名。
- [ ] 总排行榜和方向排行榜页面仍允许负责人查看。
- [ ] 排行榜列表直接渲染服务端 `items`，不在客户端删除负责人或重算 `total`/rank。
- [ ] 学生端保持现有总排名、方向排名和积分流水功能。
- [ ] 月榜与累计榜沿用现有切换，不影响本规则。

## 接口影响

- `GET /api/v1/rankings/overall`
  - 可见角色：`COLLEGE_ADMIN`、`DIRECTION_LEADER`、`STUDENT`
  - `items/total/rank` 仅包含 `ACTIVE` 学生。
- `GET /api/v1/rankings/directions/{directionId}`
  - 可见角色：`COLLEGE_ADMIN`、`DIRECTION_LEADER`、`STUDENT`
  - `items/total/rank` 仅包含该方向的 `ACTIVE` 学生。
- `GET /api/v1/rankings/me`
  - 仅 `STUDENT`。
  - `DIRECTION_LEADER` 前端不调用；后端契约不再允许该角色。

## 验收

- 同分学生仍按竞赛排名 1、1、3，不受负责人积分影响。
- 同一方向只有一名负责人和多名学生时，方向榜 `total` 等于学生人数。
- 负责人积分和积分流水与修改前一致。
- 负责人看不到“我的排名”，但仍能打开总榜、方向榜、日报和周报。
- 学生页面和 API 响应不包含负责人排名行。
