# 答辩 PPT 逐页文字稿

> 用途：2026 第九届传智杯 AI Web 网页开发挑战赛 · 5 号方向 AI 教育与学习平台
> 说明：本稿只写仓库里真实实现的功能，页面文案、接口路径、版本号均可在代码中核对；演示环节配图见 [`screenshots.md`](screenshots.md)。

## P1 封面

**标题：AI 编程实训助手 —— 让学生写完代码就有反馈**

- 一句话定位：面向编程教学的 AI 学习平台，把「写代码 → 机器判题 → AI 给分并说明依据 → 教师复核 → 成绩发布 → 过程留痕」串成一条闭环。
- 参赛信息：2026 第九届传智杯 AI Web 网页开发挑战赛，主选 5 号方向 AI 教育与学习平台，兼及 1 号 AI Agent、7 号 AI 代码开发辅助。
- 技术底牌：Spring Boot 4.1.1 + Java 21 + Vue 3.5 + 自建 Judge0 1.13.1 + Mimo `mimo-v2.6-flash`。
- 现场演示地址：前端 `http://localhost:5173`，后端 `http://127.0.0.1:8080`，接口文档 `/doc.html`。

## P2 项目背景与定位

**标题：编程课断在三个环节上**

- 练习没有反馈：写完只能等老师看，一次作业反馈周期以天计，学生练不动。
- 判分口径不统一：不同助教对同一份填空给分差异大，学生不服气，老师说不清依据。
- 学情看不见：谁在练、练到哪、卡在哪散落在聊天记录里，期中才发现有人掉队。
- 我们的定位：不是再做一个题库站，而是把「判题 + AI 评分 + 过程数据」做成教学闭环的基础设施。
- 项目来源：源自 2026 年 10 月起在学校科创空间持续使用的管理系统，参赛版按 AI 教育方向改版，原仓库继续作为生产系统运行。

## P3 核心功能①：真实判题，不是模拟

**标题：代码在隔离沙箱里真编译真执行**

- 自建 Judge0 1.13.1（隔离容器 + PostgreSQL + Redis），按语言 ID 提交，支持 Java、Python、C++、JavaScript、Go、Rust 六种语言。
- 函数式判题：学生只填函数体，服务端套 harness 生成完整程序，语法细节不干扰考核重点。
- 服务端有界并发队列，按测试点逐个执行，汇总通过率、耗时、内存；样例只回 1 个测试点，其余隐藏。
- 适配 cgroup v2 主机：Judge0 缺 cgroup v1 时返回内部错误，这里提供 rlimit 逐进程限制模式（`OJ_RLIMIT_FALLBACK=true`），已在真实环境验证到 `Accepted`。
- 试运行有每分钟 10 次限流，正式提交不限制次数。

## P4 核心功能②：AI 批改报告，一次判题一页结论

**标题：判完就能看到错在哪、下一步练什么**

- 入口 `/oj/submissions/{id}/report`，判定与失败用例、错因解析、改进建议、推荐下一题在同一页。
- 错因与建议来自与日报/周报评分同一个模型（共用 `app.ai.*` 配置，不新接模型），提示词要求按编译错误、运行错误、超时、答案错误分别解释。
- 明确不给可直接提交的题解，避免把批改变成抄答案。
- 报告只读：不写成绩、不写积分、不改任何表；结论在进程内缓存 30 分钟，刷新不重复计费。
- AI 未配置或调用失败时照常展示判题结果，并写明「AI 批改暂不可用」及原因——不生成占位批改。

## P5 核心功能③：AI 助教，会记上下文

**标题：不绑定某次提交，也能问知识点**

- 独立入口 `/tutor`：左侧会话列表，右侧对话，可关联一道题让回答结合题面。
- 会话与消息落库（`tutor_conversation` / `tutor_message`），服务端按会话取最近 12 条进提示词，前端不上传 history，也没有「换台电脑就丢对话」的 localStorage 副本。
- 提交详情页还有助教抽屉：带上这道题的题面、本次代码和判题结果，可以连续追问。
- 权限只有一条：会话归属本人；访问别人的会话 id 与不存在同样返回 404，不能用 id 探测同学开了什么话题。
- AI 不可用时仍返回 200 + `available=false` + 原因，学生这一问照样落库，刷新不会凭空消失。

## P6 核心功能④：推荐下一题，用规则不用模型

**标题：做对了升难度，做错了补同档**

- 推荐是**规则**不是模型：做对升一档（简单 → 中等 → 困难），做错同难度补练。
- 先在本场考核里找，找不到再全库找，都没有就如实返回空（`problem=null`），不硬凑。
- 首页「AI 批改与辅导」卡片只展示真实数据：最近一次已判定提交的错因摘要与推荐练习；没有记录时给空状态。
- 推荐理由里的数字全部来自真实提交，不含模型生成的判断。

## P7 核心功能⑤：学习画像，用真实数据说薄弱点

**标题：四个数字卡 + 薄弱知识点 + 推荐练习**

- 位置：AI 助教页第二个标签页；数据由后端读取时聚合本人已判题提交、判题结果与**已发布**成绩，写入快照表 `tutor_learning_profile`。
- 尝试题数按题目去重，通过 = 该题至少一次 `ACCEPTED`；薄弱知识点只取「尝试过且至少一题没通过」的标签。
- 推荐练习只从公开题库里挑还没通过的题，优先命中最薄弱标签。
- 没有做题记录时返回 `hasData=false` + 全零 + 空数组，并清掉旧快照——不拿 0% 通过率冒充画像。
- 题库练习（practice-run）不计入画像，只有正式提交算数。

## P8 AI 落地情况

**标题：AI 落在三个位置，每处都能降级**

- 落点一：主观题（日报/周报）AI 评分，按显式评分标准 `ScoringRubric` v2 给 1–3 档，只看内容具体性、可检验收获与反思，不按篇幅和文风加减分。
- 落点二：提交批改报告（错因解析 + 改进建议），与评分共用同一模型配置。
- 落点三：AI 助教对话（知识点讲解、结合题面追问、推荐练习）。
- 工程约束：异步评分 Worker 带版本号，旧版本迟到结果只标 `STALE` 不覆盖；人工结果优先于 AI；报告正文按**不可信数据**处理，prompt 明确要求忽略正文中的指令，防注入。
- 无密钥即关闭：不配置 `AI_API_KEY` 就不调用外部服务，功能如实降级而不是伪造分数。

## P9 关键技术

**标题：安全边界写在实现里，不写在文档里**

- 后端：Java 21、Spring Boot 4.1.1、MyBatis-Plus 3.5.17、Flyway 受控迁移（17 个版本到 v17，34 张表）。
- 前端：Vue 3.5 + Vite + TypeScript + Element Plus + Pinia；开发态显式关闭 CORS，只走 Vite 代理，`VITE_USE_MOCK` 不设置就不启用虚构数据。
- 判题：自建 Judge0 栈 + rlimit 兜底模式 + 有界并发队列；语言适配层按语言 ID 与函数式 harness 生成完整程序。
- AI：openai-compatible 接口，地址/模型/密钥全由环境变量注入，`AI_BASE_URL` 强制校验为干净 HTTPS origin。
- 权限与安全：三级角色（学院管理员 / 方向负责人 / 学生）+ 方向级隔离，权限在后端逐对象校验；不透明 token 只存哈希、刷新轮换、改密即撤销会话、登录限流；请求体字段集合严格校验防字段注入。
- 契约与部署：Knife4j + OpenAPI 契约驱动前后端并行；Docker Compose + Nginx 同源部署（SPA、`/api` 反代、健康检查）。

## P10 测试与验证

**标题：跑过的才算数**

- 自动化：后端 `./mvnw test` **222 个用例通过**（0 失败、0 错误、4 跳过，22.6s）；前端 `pnpm test` **55 个文件 / 259 个用例全通过**（22.9s）。
- 端到端：`docs/test-notes.md` 记录 13 条操作验收 + 3 个重点确认项**全部通过**（学生改密、试卷三件套、试运行限流、提交判定、报告降级、助教会话、画像空/有数据、阅卷发布、人工覆盖自动分、管理员看板）。
- 重点项实测结论：考核截止后**自动代交草稿**并置 `CLOSED`；进行中**不限制**正式提交次数；题库练习**不计入**学习画像。
- 真实环境：Judge0 在本机 cgroup v2 环境下用 Python 样例验证到 `Accepted`；AI 配置后 `/api/v1/tutor/chat` 实测返回 `mimo-v2.6-flash` 真实回答（`available=true`）。
- 如实说明：后端 `*IT` 集成测试需 Docker + Testcontainers，本机未跑；COS 图片上传未验证（未配置凭据，不影响主链路）。

## P11 团队分工

**标题：五条线并行，接口契约对齐**

- 后端与判题线：Spring Boot 服务、Judge0 适配器、判题队列、阅卷与成绩发布、权限校验。
- 前端线：Vue 页面与状态管理，OJ 考核/提交、日报周报、看板与排行榜，Element Plus 组件封装。
- AI 集成线：评分标准（`ScoringRubric` v2）、异步评分 Worker、批改报告与助教提示词、降级策略。
- 测试与验收线：13 条操作验收 + 重点项实测、权限与安全边界检查，产出 `docs/test-notes.md`。
- 视频与答辩线（本人）：演示脚本、截图清单、PPT 逐页稿与答辩问答准备。
- 协作方式：先定 OpenAPI 契约再并行开发，前后端各自跑通后按验收表逐项回归。

## P12 收束（可选页）

**标题：一句话总结 + 演示路线**

- 一句话：把「等老师批」变成「判完就有依据」，让编程课的反馈周期从以天计变成以秒计。
- 现场演示路线（约 4 分钟）：学生首页 AI 卡片 → 题库 → 题目详情提交 → 提交记录 → 批改报告 → 助教对话 → 学习画像。
- 可追问点：为什么推荐用规则不用模型、AI 不可用时系统如何表现、权限为什么放在后端。
